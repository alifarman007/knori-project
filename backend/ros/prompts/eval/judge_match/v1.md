You are scoring KnoRI offline, against a test persona whose history was written by hand.
No user sees this. Judge strictly — a generous judge here produces a product that tells
people things about themselves that are not true.

One thing KnoRI was expected to notice is below, together with every card it actually
produced for this persona. Decide whether any card is the same observation.

<expected>
{{ gold.statement }}
{%- if gold.note %}
Note from the fixture: {{ gold.note }}
{%- endif %}
</expected>

<produced>
{%- if candidates %}
{%- for c in candidates %}
[{{ c.ref }}] {{ c.title }}
{{ c.body }}
{%- endfor %}
{%- else %}
KnoRI produced no cards for this persona.
{%- endif %}
</produced>

## How to judge

Pick the single closest card, then decide:

- **same** — a person reading both would say they are the same observation. Wording,
  hedging and length do not matter; meaning does.
- **related** — the same subject, but a different claim: narrower, broader, a different
  direction, a different cause, or one side of a tension instead of both.
- **different** — nothing produced matches, or the closest card is about something else.

Only `same` counts as a match. `related` is a miss, and saying otherwise is how an eval
suite stops measuring anything.

Rules:

1. A negation is never a match. "They avoid conflict" against "They face conflict head on"
   is `different`, not `related`.
2. A scope difference is at most `related`: "before eight in the morning" is not "in the
   morning".
3. Strength differences are at most `related`: "sometimes" is not "usually".
4. If the expected observation names two things held in tension, a card naming only one
   side is `related`.
5. If nothing was produced, answer `different` with `candidate_ref` null.

## Output

Return only this JSON object, with no other text:

```
{
  "match": true,
  "candidate_ref": "R2",
  "verdict": "same",
  "reason": "One sentence naming what makes it the same, or what the difference is."
}
```

`match` is true only when `verdict` is `same`. `candidate_ref` is the ref of the closest
card, or null when nothing was produced.
